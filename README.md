# Polymarket 5 分钟涨跌 · 发布即预挂机器人

参考 [huice](https://github.com/7CCCCC21X/huice) 的「15 分钟市场发布即预挂」（`preopen.py` / `PREOPEN.md`）改写到 Polymarket：
每个 5 分钟涨跌市场一发布，就在**涨、跌两边各挂一张 post-only 限价买单**（默认 49¢ × 10 份），
排在队列前面；**开场前撤单**，订单自带 GTD 到期时间兜底。两边都成交 = 一对成本 98¢、到期必得 $1 的无风险组合；
只成交一边 = 49¢ 买到一个五五开的结果。

首批市场（`PREOPEN_MARKETS=all`，默认）：

| 币种 | 链接规律（`<开始时间的 Unix 秒>`，5 分钟一场） | 例子 |
| --- | --- | --- |
| BTC | `btc-updown-5m-<t>` | https://polymarket.com/zh/event/btc-updown-5m-1794536700 |
| ETH | `eth-updown-5m-<t>` | https://polymarket.com/zh/event/eth-updown-5m-1794536700 |
| SOL | `sol-updown-5m-<t>` | https://polymarket.com/zh/event/sol-updown-5m-1794537300 |
| XRP | `xrp-updown-5m-<t>` | https://polymarket.com/zh/event/xrp-updown-5m-1794536700 |
| DOGE | `doge-updown-5m-<t>` | https://polymarket.com/zh/event/doge-updown-5m-1794536700 |
| HYPE | `hype-updown-5m-<t>` | https://polymarket.com/zh/event/hype-updown-5m-1794536700 |
| BNB | `bnb-updown-5m-<t>` | https://polymarket.com/zh/event/bnb-updown-5m-1794536700 |

`t` 是这一场的开始时间（UTC 秒，300 的整数倍），例如 `1794536700` = 北京时间 11-13 10:25（美东 11-12 9:25PM），
结束于 `t + 300`。机器人不需要你逐场添加：它按规律算出接下来每一场的链接，发布了就挂。

## 实测的市场规律（2026-11-13）

- **发布时间**：每一场在开场前约 **23 小时 52.5 分**创建（`createdAt`，中位 85,948 秒），七个币在同一秒内；偶尔晚一两分钟。
- **创建 ≠ 能下单**：刚创建的市场 `active=false`、`acceptingOrders=null`，交易所不接单；约 **75～90 秒后才激活**
  （`active`、`acceptingOrders` 和 CLOB 的接单标志 `ao` 同时变成 true）。`acceptingOrdersTimestamp` 字段写的是创建后约 6 秒，
  是事后回填的，不能信。激活后 1 秒内盘口上就有人挂了 200 多份（BTC：激活后 1 秒 50¢ 230 份；10 秒后 49¢ 281 份；30 秒后 482 份），
  所以真正的比赛起点是「激活那一刻」。
- **两种查法差 88 秒**：`GET /markets/slug/<slug>`（按路径）在创建后 **0.5 秒**就能查到，字段齐全（conditionId、两个代币、开始结束时间）；
  而批量查询 `GET /markets?slug=...`（以及 `/events?slug=`）只返回已激活的市场，要等到激活后才出现。机器人用路径接口盯每个币的下一场，
  提前约 80 秒拿到代币、预填 SDK 的市场缓存（签名不再联网），创建后 55 秒起每 0.2 秒问一次 CLOB 是否接单，一开放七个币并行下单。
- **Gamma 有 5 分钟缓存**：`/markets` 的应答带 `cache-control: max-age=300`，CloudFront 会把「还没发布」的空结果缓存
  最多 5 分钟（实测 `x-cache: Hit, age: 264` 时市场已发布 4 分钟仍返回 `[]`）。机器人每次请求都带一个独一无二的参数绕开缓存。
- **结算**：Chainlink 60 秒 TWAP（开场价和结算价都是 TWAP），开场后约 80 秒出结果（`outcomePrices` 变成 `["1","0"]` 或 `["0","1"]`）。
  开场前几分钟盘口就会因为行情偏离五五开（实测开场前 5 分钟 BTC 涨被买到 55¢），越接近开场成交越可能是「知道方向的人」吃你的单，
  所以默认**开场前 60 秒撤单、30 秒到期**，比 huice 的 20/10 秒保守。
- **手续费**：这些市场只收吃单方手续费（`feeSchedule.takerOnly=true`，费率 0.07），post-only 挂单永远是挂单方，不付手续费，
  还可能分到挂单返佣（taker 手续费的 20%）。若某个市场改成挂单方也收费，机器人不挂它。
- **流动性奖励**：这些市场 `rewardsMinSize=50`、`rewardsMaxSpread=4.5`¢：每边 ≥50 份、离中间价 4.5¢ 以内的挂单可能计入奖励。
- **最小单位**：价位 0.01（价格接近 0/1 时变 0.001），最小 5 份。

## 资金：每个市场分别核对余额，不共用

Polymarket 按**市场**核对挂买单：同一个市场（一场）里的挂买单合计不超过余额就能挂，**别的市场的挂单不算在内**。
11-13 在网页上实测：余额 $75.10，在三个不同的 BTC 场次各挂 $49（合计 $147），三张都挂上了。
（官方文档 Order Lifecycle 写的是 `maxOrderSize = balance − Σ(openOrderSize − filledAmount)`，没写按不按市场；
上一版据此改成了「所有挂单共用一份余额」，实测证明不对，已改回按市场。）

- 默认 49¢ × 10 份，一场两边共 $9.80。**余额只要 ≥ 一场所需，就能把范围内的全部场次都挂上**
  （七个币一天约 2016 场，挂单合计上万美元也没关系，每场各自对照余额）。
- 一场能不能挂，只看这一场自己（它在这场已挂的单、网页或别的策略在这场挂的单）和余额。设了深档时，每场按顺序放得下几档挂几档。
- `PREOPEN_MAX_OPEN_USD` 是本程序**全部挂单合计**的上限（0 = 不限）：想限制同时挂多少场时用，开场最近的先挂。
- **成交会花掉余额。** 余额一旦低于某一场的挂单合计，交易所会撤掉那一场的单（`CANCELED_NOT_ENOUGH_BALANCE`）。
  余额比一场所需多出的部分就是「成交缓冲」：缓冲越大，越多次单边成交后挂单仍然有效。被这样撤掉的场次不算失败，
  余额回来后（结算、领取）自动重挂。建议余额留一场所需的几倍，并设上 `PREOPEN_MAX_EXPOSURE_USD`（持仓最坏亏损）。
- 概览页「范围内」一行列出范围内每一场现在的状态：挂着、排队、等开放、资金不够、暂停中、不挂（及原因）。
  `python main.py probe` 会显示每场所需和全挂上的挂单合计。

## 规则

| 项目 | 行为 |
| --- | --- |
| 订单 | 两边各一张 **BUY 限价、post-only、GTD**：会吃单的直接被交易所拒绝，不会主动成交 |
| 价格与份数 | 第一档 `PREOPEN_PRICE_CENTS` × `PREOPEN_SHARES`；`PREOPEN_LEVELS=48x20,47x40` 在下面再挂更深的档，`PREOPEN_DEEP_AHEAD_MINUTES` 限定深档只在开场前多久才挂 |
| 范围 | 只挂 `PREOPEN_AHEAD_MINUTES`（默认 1440）分钟内开始的场次；最新发布的最先挂，其余按开场时间最近的先 |
| 新单截止 | 距开场不足 `PREOPEN_ENTRY_SECONDS`（默认 300）秒不再新挂 |
| 撤单 | 开场前 `PREOPEN_CANCEL_SECONDS`（默认 60）秒按订单号撤（开场最近的先），状态不明的单按订单哈希撤；没撤掉的每 2 秒再撤。开场前因暂停、改设置提前撤单失败时，重试间隔最长 2 分钟，但绝不会晚过撤单时刻。**只撤本程序自己签的单**：同一个 API Key 下别的策略、网页上的挂单都不碰（见下面「凭证范围」） |
| 凭证范围 | `PREOPEN_KEY_EXCLUSIVE=off`（默认）：认为这个 API Key 可能还有别的策略在用，只按订单号/哈希撤自己的单。`=on`：确认 Key 只给本程序用，到撤单时间再按整个市场扫一遍兜底，紧急停止和切到模拟盘时一次撤光这个 Key 的全部挂单 |
| 到期兜底 | 订单在开场前 `PREOPEN_EXPIRY_SECONDS`（默认 30）秒自动失效（GTD 的到期时间写成 `开场 − 到期秒数 + 60`，交易所提前 60 秒失效） |
| 单边异常 | 一边被拒或没发出，另一边立刻撤掉；之后这一档重新报价（换新订单），不重签补单。结果不明的一边先按订单哈希找 30 秒：找到就照常挂着（排队位置不丢），找不到才把这一档撤掉 |
| 重新报价 | 开场前被撤掉、没有成交的档位会重新报价：因自身原因失败的（单边被拒、挂单被别人撤掉）每档最多 `PREOPEN_MAX_ATTEMPTS` 次，间隔 60 秒；改设置、暂停、限流、市场还没开放、余额不足、交易所因市场或到期撤单这类不算次数。两边都没挂上、原因又不在这一场（还没开放、限流、余额）的不留记录，直接重来（市场还没开放时 0.2 秒后重试）。有成交的、被交易所判定为无效订单的不再报 |
| 余额 | 每场分别对照余额（见上面「资金」）：余额不够这一场就先不挂这一场，别的场照常。交易所因余额不足撤掉某些场次的单（`CANCELED_NOT_ENOUGH_BALANCE`）时马上重读余额，这些场次等余额回来再挂；交易所下单时拒单说余额不够（说明本地看到的不准，比如授权额度不够、别的 Key 在这一场挂的单），全部新挂暂停 1 分钟并重读余额。**这些都不算场次失败**，场次不会因此作废 |
| 被别处撤单 | 本程序的挂单被别处撤掉（网页上点了撤单或「取消所有」、别的程序用同一个 Key 撤单）：只有一两场时，算这一场失败一次、60 秒后重挂；**60 秒内 3 场以上被撤**，当成「要停」：自动暂停、撤掉其余挂单、发通知，不算任何场次失败，在控制台点「恢复挂单」或发 /resume 继续 |
| 交易所拒单 | 按拒单原文分类（官方错误码表）：**只有和这一场这张单有关的**（post-only 会吃单、价格不在最小价位上、份数低于最小值）才算这一场失败一次，最多重挂 `PREOPEN_MAX_ATTEMPTS` 次。其余的（余额、到期时间规则、账户被限制、整批请求被拒、看不懂的原文）都是账户层面的：**不作废任何场次**，全部新挂暂停 30 秒、连续被拒就加倍到最长 10 分钟，概览页顶部写明原因；看不懂的拒单只有在别的场次都能挂、也没有别的场次被同样的话拒掉、只有这一场一直被拒时，才算这一场自己的问题。`could not insert order`（交易所自己插单失败）等 5 秒重发。`order timed out`（500）按官方说明是没进订单簿，直接重发；`Duplicated` 说明这张单已经在簿上，按哈希找回。以前的版本把整批 400、看不懂的拒单、被别处撤了 3 次当成「不再挂」，启动时会把这些被停掉的场次恢复 |
| 先落盘再发送 | 每张单发出前写两次账本：先写记录（发送中），签名后、发出第一个字节前再写订单哈希（就是交易所的订单号）。进程在发送途中被杀，重启后也能按哈希找到这些单、撤掉它们、读到它们的成交 |
| 结果不明 | 下单超时、应答丢失、进程在发送中停止、交易所回了普通 5xx 等「不知道挂没挂上」的单：按订单哈希查单、在挂单列表里按哈希**精确**认领；它的资金一直算作占用，这一档也不会重新报价。只有两种情况才下结论：交易所明确说没有这个订单号（订单号已确认等于哈希，且发出 2 分钟后仍查无此单），或者签名的到期时间已过——此时它不可能再挂着，按账户的成交记录核实它买到多少（查不到就标记「待核实」并提醒你到 Polymarket 核对）。没有哈希可用时才按 代币/价格/份数 认领，而且只在恰好一张同规格的单时认领，两张以上（可能是别的策略的）一律不认 |
| 账户快照 | 每 10 秒读一次全部挂单、每 30 秒读一次余额：发现成交（通知）、发现挂单不见了（读最终记录，读不到再查成交记录）、算资金占用。挂单列表和余额**分别**检查新旧：任何一个过期（挂单约 45 秒、余额约 105 秒没读到新的）就暂停新挂 |
| 限流与拒单 | **同一时间只发一个下单请求**：交易所对同一账户的并发下单会回 `order timed out`（官方说明），所以 8 个工作协程各自签名后，由一个发送器排队发出，等着的场次合在一起，一次最多 15 张单（7 场），一场的两边不拆开；`order timed out` 时暂停新挂 5 秒、连续超时加倍到最长 60 秒。重启后要把几百场全挂上时，大约 1 分钟挂完（受本地令牌桶限制）。本地令牌桶（下单 30/秒、撤单 60/秒，低于 Standard 档位的 40/80）；交易所回 429、撮合引擎重启（425）、只许撤单 / 只许挂单 / 交易已停用（503 且明确写了原因）、认证失败（401/403）时整体冷却，按服务器给的时间重试——**只有这些明确说「没处理」的拒绝**才算没发出；普通的 503/502/504、超时一律按「结果不明」处理。被判为没发出的单仍会按哈希撤一次，万一判断错了也不会留下没人管的挂单。公共接口（Gamma、CLOB 公共读）回 429 时按 `Retry-After` 停问，超时和错误不会被当成「市场不存在」 |
| 风控 | `PREOPEN_MAX_EXPOSURE_USD`：还没结算的场次里，单边成交（没配成对的份数）最坏会亏的钱到这个数，就撤掉还没成交的挂单、不再新挂，结算后自动恢复（有成交那一场的另一边留着，它成交只会把单边配平）。`PREOPEN_MAX_DAILY_LOSS_USD`：今天（北京时间）已结算亏损到这个数，同样撤单停挂，零点后恢复。都默认 0 = 不限 |
| 重启、改设置 | 挂单留在簿上（到期自动失效），新进程按账本接管：和当前设置一致的原样保留（排队位置不丢），不一致的撤掉按新设置重报。`PREOPEN_CANCEL_ON_EXIT=on` 则退出时撤单 |
| 结算与领取 | 窗口结束约 1 分钟后读官方结果算盈亏；实盘且 `PREOPEN_AUTO_REDEEM=on` 时自动领取赢的一边（智能钱包需要 Relayer Key；EOA 钱包需要 POL 付 gas；失败的 10 分钟后再试，最多 6 次，也可以在网页上手动领取） |
| 暂停 | `/pause`：不再新挂，撤掉本程序的全部挂单（状态持久保存，重启后仍暂停）；`/resume` 恢复 |

## 部署（Railway）

1. 把本仓库连到 Railway（Deploy from GitHub repo），使用仓库里的 `Dockerfile` 和 `railway.json`，启动命令 `python -u main.py`。
   这是常驻进程：**不要配健康检查和 Cron**。构建时会跑全部离线测试，测试不过构建失败。想用网页控制台就生成一个域名（见下文「网页控制台」）。
   **地区必须选 EU West（Amsterdam）**：Polymarket 对美国、新加坡、英国、法国、德国、澳大利亚等地的 IP 在 API 上也只许平仓、不许开新单
   （Railway 的 US West / US East / Southeast Asia 区都下不了单）；荷兰只限制网页、不限制 API。Polymarket 的服务器在 AWS 伦敦（eu-west-2），
   Amsterdam 到那里延迟最低。实盘启动时机器人会查一次 `polymarket.com/api/geoblock` 并在日志/Telegram 里报出所在国家，受限就告警。
2. 给服务挂一个 **Volume 到 `/data`**（账本 `/data/preopen.sqlite3` 必须在持久卷上，否则重启后不认识自己挂着的单）。只运行一个副本：
   同一个账本同时只能有一个进程（账本旁边有文件锁 `preopen.sqlite3.lock`，第二个进程会报错退出），免得同一场挂两遍。
   账本记着它属于哪个账户（钱包 + 签名地址）：换了私钥或钱包，机器人不会接管旧账户的记录，也不新挂，网页上会提示——换回原来的私钥，
   或者先到 Polymarket 撤掉旧账户的挂单、再在网页上点「改绑当前账户」（也可以把 `PREOPEN_DB` 换成新文件从头开始）。
3. 先不填私钥、保持 `LIVE=off` 跑模拟盘，看日志或 Telegram `/status`：每场发布后几秒内是否「挂上」、开场前是否撤掉。
4. 准备实盘账户（建议单独开一个账户给机器人）：
   - `POLY_WALLET`：polymarket.com 右上角个人菜单里显示的钱包地址；
   - `POLY_PRIVATE_KEY`：这个账户的签名私钥（邮箱/Google 登录的账户可在网页设置里导出；MetaMask 等外部钱包就是那个钱包的私钥），
     或者一把已授权给这个 Deposit Wallet 的 **Session Key**（只能交易、不能提现，更安全；但可能不能自动领取，领取可在网页上做）；
   - `POLY_API_KEY` / `POLY_API_SECRET` / `POLY_API_PASSPHRASE` **一般不填**：程序用私钥自动生成。填了就必须是同一把私钥生成的，
     否则每张单都会被拒（`the order signer address has to be the address of the API KEY`，🩺 体检会直接提示）；
   - 自动领取：在 设置 → API Keys → Relayer API Keys 建一个 Key，填 `POLY_RELAYER_API_KEY` 和 `POLY_RELAYER_API_KEY_ADDRESS`；
   - 账户里要有 **pUSD**，并在网页上至少交易过一次或完成交易授权（SDK 也会在缺授权时尝试补上）。
5. 先在本地或 Railway 上跑 `python main.py probe`（只读，不需要私钥）确认市场都找得到、资金需求，再设 `LIVE=on`。

## 本地运行

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt  # 或者和镜像完全一致：pip install --require-hashes --no-deps -r requirements.lock（Python 3.12）
cp .env.example .env            # 按需修改
python main.py probe 1          # 只读探测：接下来 1 小时的场次、发布规律、盘口、资金需求
python -u main.py               # 运行（LIVE=off 时是模拟盘）
python main.py status           # 看本地账本的记录数和盈亏
python tests/run_all.py         # 离线测试（不联网、不需要私钥）
```

## 网页控制台

机器人自带一个网页控制台（参考 huice 的 `/control` 和复盘页），手机电脑都能用。顶部常驻状态条（实盘/模拟、运行/暂停、挂着多少场、余额、每场占用、今日盈亏），下面四页：

| 页 | 内容 |
| --- | --- |
| **概览** | 资金与成交卡片、运行情况（范围内每一场的状态、已发布到哪一场、下一场几点发布、账户快照、限流档位）、**待处理**（状态不明的单、撤单没确认、账户里本程序没记录的挂单、接口冷却）、开场最近的 40 档挂单、有成交的场次、最近的问题；每 5 秒刷新；部署了新版本后，开着的页面会自己重新加载 |
| **参数** | **在线改参数**：每项一张卡片，点预设值或填自定义值后保存，**立即生效**并保存到 `/data/preopen.control.json`，重启后仍按网页的值运行；网页上的值**高于 Railway 变量**。卡片上标明现在的值来自「网页 / 环境变量 / 默认」，可「恢复环境变量」单项撤销，或「清除全部」。保存时和启动时一样整体校验，不合法的什么都不改并说明原因。改参数时和新参数一致的挂单原样保留（排队位置不丢），不一致的撤掉后按新参数重挂。分组：运行（真实交易开关）、预挂策略（挂哪些币，可一键全开/全关；价格；份数；深档；提前范围；撤单/到期/新挂时间；周末）、资金与风控（每场资金上限、持仓最坏亏损上限、日亏损上限、重报次数、自动领取、退出时撤单）、高级（扫描与限速、API Key 是否只给本程序用，默认收起）。私钥、API Key、Token、钱包、`WEB_KEY` 只能在 Railway 变量里改 |
| **订单** | 挂着 / 有成交 / 已撤无成交 / 全部 四个标签（带数量），按币种筛选；每场每档的涨跌两边状态、成交、第几次报价、原因或结果、盈亏；挂着的可以单独「撤」（撤后这一档不再重挂）。手机上每笔两行显示 |
| **复盘** | 今天 / 近 7 天 / 累计（报价场次、成交场次和成交率、双边、赢输、成本、盈亏、收益率）；按日期、按币种、按开场时段、按方向（涨/跌各成交多少、赢回多少）、按**成交时距开场**（开场前 1 分钟内 / 1～5 分钟 / … ——越靠近开场的成交越可能来自知道方向的人，这一栏盈亏偏负就把撤单提前）；成交明细（挂上时距开场、撤单确认、首次成交距开场、第几次报价）；导出成交明细 CSV、每日汇总 CSV |

操作按钮：「⏸ 暂停并撤单」「▶️ 恢复挂单」「🛑 紧急停止」（暂停，并马上撤掉本程序签的全部挂单，状态不明的按哈希撤；`PREOPEN_KEY_EXCLUSIVE=on` 时再一次撤光这个 API Key 的全部挂单）。账本和当前账户对不上时，概览页顶部会出现说明和「改绑当前账户」按钮。

**真实交易开关**也在参数页：切到 on 需要 Railway 里有 `POLY_PRIVATE_KEY`；切换后程序自动重启（约半分钟）；从实盘切回模拟盘前会先撤掉本程序的全部真实挂单（`PREOPEN_KEY_EXCLUSIVE=on` 时撤光这个 API Key 的全部挂单）。

打开方法（Railway）：

1. 打开这个服务 → **Settings → Networking → Generate Domain**，生成一个 `xxx.up.railway.app` 的域名（端口用 Railway 默认的 `PORT`，机器人自己会监听）。
2. 在 **Variables** 里加 `WEB_KEY`（至少 12 位的密码），重新部署。
3. 浏览器打开 `https://xxx.up.railway.app`，输入 `WEB_KEY` 登录（保持登录 30 天）。
   - 填了 Telegram 的话，**不用密码**：点机器人聊天框左下角的菜单按钮「控制台」，网页直接在 Telegram 里打开，用 Telegram 的签名认证（只认管理员：`TELEGRAM_ADMIN_IDS` 里的用户，没填就是 `TELEGRAM_CHAT_ID` 这个私聊用户）。
4. 网页保存的设置和账本一样放在 `/data`，所以 **Volume 一定要挂**，不然重启后网页设置就丢了。

### 撤单时间复盘：开场前几秒撤单最好

每场结算时，机器人从交易所的成交记录里读出**每一笔成交的准确时刻**（读不到时用账户快照看到的时间，偏晚几秒，会标出来）。
网页「复盘」页、📈 复盘 和导出的「撤单时间复盘」CSV 里有两张表：

- **结论放在第一行**：「改成开场前 X 秒撤单最好：会是 +A 美元，实际是 B」，下一行「亏在哪」列出亏得最多的成交时段，
  有成交发生在撤单确认之后或开场之后（撤单没生效）会单独警告，没设日亏损上限也会提醒。
- **如果提前撤单**：把每一场按「如果开场前 X 秒就撤单」重算——X 秒之后才成交的单当作没成交——算出每个 X 的盈亏，
  第一行是实际发生的。所有行用同一批场次，可以直接比较；结果一样的相邻几行合成一行；「★最好」是盈亏最高的（有成交的场次满 20 场才给结论）。
  因为重启、改设置、拒单等原因提前结束的场次，不管撤单设成几秒都一样，全部算在内。
  **只能算比当时撤得更早的情况**：比如现在是开场前 15 秒撤，10 秒的情况就算不出来（那 5 秒单子已经撤了，不知道会不会成交）。
  想试更晚撤，先把撤单时间改小跑一段，再来比。
- **一键应用**：Telegram 复盘消息下面有「改成开场前 X 秒撤单」按钮，点一下立即生效并保存（和网页上改一样）。
  同时把「距开场不足几秒不再新挂」调到至少比撤单多 60 秒，把订单自己的到期时间提前到撤单后 5 秒左右——撤单万一失败，
  订单也会自己失效，不会挂到开场前最后几秒（GTD 订单在写明的到期时间前 1 分钟失效，这是交易所的规则）。到期时间变了，
  挂着的单会按新到期时间重挂一遍，约 1 分钟。
- **什么时候成交的**：按成交时刻离开场多少秒分组，看买到的那一边最后赢的比例。低于保本线（=买价）的时段，成交是亏的：
  越靠近开场的成交越可能来自知道方向的人，这一栏变红，就把撤单时间提前到它之前。

改撤单时间在网页「参数」页的「撤单」一项，立即生效。

### 自检：点 🩺 体检（或发 `/check`）

第一行是结论，下面每项前面的标记：✅ 正常、⚠️ 要看一下、⛔ 停了、ℹ️ 只是信息。

| 结论 | 意思 |
| --- | --- |
| ✅ 正常：… | 范围内已发布的场次都挂着（「还没发布」的是 Polymarket 还没上线的场次，正常） |
| ⏳ 正在挂：… | 刚启动或刚恢复，还在排队挂，一两分钟后再点一次 |
| ⚠️ 有 N 场没挂 | 看【挂单】的「范围内」一行：资金不够、被拒停挂、失败 3 次、手动撤了等，括号里是原因 |
| ⛔ 暂不新挂：… | 后面就是原因：交易所拒单（附交易所原话）、冷却、余额或快照过期、风控等 |
| ⏸ 已暂停 | 点 ▶️ 恢复；网页上「取消所有」成批撤掉本程序的单也会自动暂停 |

其余几块：【挂单】下单是否被交易所接受、是否超时、状态不明的单；【资金】余额够不够一场、挂单合计、
领取（没配 Relayer Key 会提示怎么配）、风控；【账户与接口】账户快照、限流档位、发现市场到哪一场、公共接口；
最后是最近 10 分钟的问题原文。要问人时，把体检的整条消息截图或复制过来就行。

另外两个只读的：📊 状态 是简要概况；🔎 探测（`/probe 2` = 接下来 2 小时）不用私钥，直接问 Polymarket 公共接口，
看市场找不找得到、发布规律、盘口和资金需求。

## 代码结构

| 文件 | 作用 |
| --- | --- |
| `main.py` | 入口：`run` / `probe` / `status` |
| `preopen/config.py` | 读环境变量并校验（价格不超过 50¢、GTD 的 3 分钟规则、撤单早于到期等） |
| `preopen/markets.py` | 链接规律、范围内的场次、Gamma 市场字段的校验（涨/跌按名字对应代币） |
| `preopen/gamma.py` | 公共读接口：Gamma 批量查链接（绕缓存）、CLOB 是否接单、盘口 |
| `preopen/exchange.py` | 交易所适配：实盘走官方统一 SDK `polymarket-client`（签名、15 张一批下单、按单号/按市场撤单、挂单列表、余额、领取），模拟盘在内存里 |
| `preopen/engine.py` | 控制器：发现、下单队列、到点撤单、核对、账户快照、结算与领取、接管 |
| `preopen/ledger.py` | SQLite 账本：先落盘再发送；两天前无成交的记录归档 |
| `preopen/web.py` | 网页控制台（自带的小 HTTP 服务，`WEB_KEY` 或 Telegram 签名登录） |
| `preopen/console.py` / `preopen/journal.py` | 控制台后端：网页保存的设置（校验、即时生效、重启后沿用）、操作、订单列表、复盘统计与 CSV |
| `preopen/telegram.py` / `preopen/probe.py` / `preopen/region.py` | Telegram 通知、按钮与命令，只读探测，实盘前的所在地区检查 |
| `tests/` | 离线测试（假 Gamma、假 SDK、可控时钟）；`tests/test_review.py` 逐条复现审查指出的问题并证明已修复 |

直接依赖只有 `polymarket-client`（官方统一 SDK，固定 0.18.0；它还在 0.x 阶段、接口常变，所以所有调用都集中在 `preopen/exchange.py`）和 `httpx`（`requirements.txt`）。
镜像安装的是 `requirements.lock`：连同间接依赖共 34 个包，版本和文件哈希全部锁定（`pip install --require-hashes`），除了特意固定的 SDK 外都是发布满两周的版本；
基础镜像 `python:3.12-slim` 也按 digest 固定。生成方法写在 `requirements.lock` 开头。

## 风险提示

- post-only 只保证下单那一刻不吃单，挂着的单随时可能被成交；撤单不能撤回已经成交的部分。
- 只成交一边是方向性风险（49¢ 买一个五五开的结果）。开场前越近，成交越可能来自知道方向的人，撤单时间不要设得太晚。
- 交易所维护、限流、网络故障都可能让撤单晚到；GTD 到期是最后一道兜底。
- 建议设上 `PREOPEN_MAX_EXPOSURE_USD`（持仓最坏亏损）和 `PREOPEN_MAX_DAILY_LOSS_USD`（日亏损）两个上限，先小后大。
- API Key 最好只给本程序用；和别的策略共用时保持 `PREOPEN_KEY_EXCLUSIVE=off`（默认），本程序只会撤自己签的单。
- 请先用模拟盘和小资金验证。实盘的一切盈亏由使用者自己承担。
